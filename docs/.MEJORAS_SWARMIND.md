## 1. 🐛 Fix Crítico: LanceDB check prematuro al importar el paquete

**Problema:**
`harness/__init__.py` importaba `from harness.run import main as run` a nivel de módulo.
Esto ejecutaba el check de LanceDB (`sys.exit(1)` si no instalado) **al importar cualquier cosa del paquete `harness`**, incluso si solo se quería usar `TaskManager` o `LanceVectorStore`.

**Solución:**
- `harness/__init__.py`: Eliminado import directo de `run.py`. Ahora usa `run_main()` con lazy import.
- `harness/run.py`: Check de LanceDB movido de módulo → función `_check_lancedb_or_exit()` dentro de `main()`. A nivel de módulo solo hay warning, no `sys.exit()`.
- `harness/__main__.py`: Actualizado para usar `run_main()`.

**Impacto:** Ahora se puede importar `harness` sin disparar el check de LanceDB.

### 11.11 Arquitecturas RAG frontier — híbrido RRF + correctivo CRAG (2026-08-18)
**Problema:** la recuperación RAG usaba `LanceVectorStore.hybrid_search` (vector + filtro keyword en metadata, NO BM25 real fusionado) y no había validación de calidad del contexto ANTES de generación — contexto pobre llegaba al LLM sin corrección.
**Solución:** (1) Evaluación de las **5 arquitecturas RAG 2026** (FRS): híbrido, GraphRAG, agentic, CRAG, multimodal. (2) **Híbrido RRF IMPLEMENTADO** — `harness/memory_rag/hybrid_retriever.py` (NUEVO): `HybridRetriever` fusiona vector denso (LanceDB embeddings) + BM25 disperso (SQLite FTS5) con **Reciprocal Rank Fusion** (k=60, Cormack 2009); `HybridResult` (dataclass frozen: doc_id, score, dense_rank, sparse_rank, metadata); DI sobre `FTSSearch` + `LanceVectorStore`; `DENSE_WEIGHT`/`SPARSE_WEIGHT` exportados. (3) **Correctivo CRAG IMPLEMENTADO** — `harness/memory_rag/corrective_retriever.py` (NUEVO): `CorrectiveRetriever` valida calidad de recuperación pre-generación (Yan et al., arXiv:2401.15884); evaluador heurístico cero-LLM (score medio normalizado + cobertura de términos); umbral 0.30; si pobre → query rewrite (expansión de keywords) o fallback a fuente alternativa; reporta `corrective_action` (none/rewrite/fallback) + `quality_score`. (4) **GraphRAG CUBIERTO** (documentado): `knowledge_graph.py` + TokenBudgetRouter (PageRank + TF-IDF); pipeline LLM de entidades = YAGNI. (5) **Agentic RAG CUBIERTO** (documentado): orchestrator multi-agente. (6) **Multimodal PARCIAL** (documentado): anydoc binarios → Markdown; embeddings multimodales = YAGNI.
**Tests:** `test_hybrid_retriever.py` (12) + `test_corrective_retriever.py` (10) = 22 tests nuevos; regresión memory_rag **191 passed**; ruff 0 errores. **Verificación real (smoke):** CASO 1 calidad buena → `action=none`; CASO 2 calidad pobre → `fallback` exitoso (quality 0.91); heurística discrimina 0.91 vs 0.06; fusión RRF ordena doc en ambos rankings > doc solo denso rank 1 > doc solo sparse.
