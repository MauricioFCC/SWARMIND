## 1. 🐛 Fix Crítico: LanceDB check prematuro al importar el paquete

**Problema:**
`harness/__init__.py` importaba `from harness.run import main as run` a nivel de módulo.
Esto ejecutaba el check de LanceDB (`sys.exit(1)` si no instalado) **al importar cualquier cosa del paquete `harness`**, incluso si solo se quería usar `TaskManager` o `LanceVectorStore`.

**Solución:**
- `harness/__init__.py`: Eliminado import directo de `run.py`. Ahora usa `run_main()` con lazy import.
- `harness/run.py`: Check de LanceDB movido de módulo → función `_check_lancedb_or_exit()` dentro de `main()`. A nivel de módulo solo hay warning, no `sys.exit()`.
- `harness/__main__.py`: Actualizado para usar `run_main()`.

**Impacto:** Ahora se puede importar `harness` sin disparar el check de LanceDB.

### 11.2 GPU enablement CUDA 12.6 (RTX 4060)
**Problema:** torch era CPU-only — la GPU física (RTX 4060 8GB) estaba presente pero inutilizada.
**Solución:** wheels CUDA 12.6 instalados (torch 2.13.0+cu126). `gpu_accel.py` con `get_device_info()`, `zeros(on_gpu=True)`, `to_cpu()`/`to_gpu()` con semántica corregida. `gpu_optimize.py` con embeddings vectorizados (Knuth hash numpy, DRY con `common.fallback_embedding`), hashing y normalización en GPU vía `torch.index_add_`, `gpu_self_test`. `health.py` con `get_hardware_info()` en liveness. `scripts/enable_gpu.py` portable (reinstala CUDA tras cada `uv sync`).
**Speedups medidos:** vector search **x10.9 (10k)** / **x9.2 (100k)**; embeddings batch **41µs/mensaje**; cache semántico x1.3.

### 11.3 ParallelExecutor — paralelismo y votación nativos (aportación ORCA 2026)
**Problema:** ORCA (stablyai/orca), ADE para flota de agentes en paralelo, evaluado con mesa de 5 especialistas: no embebible (Electron/TS sin SDK Python), worktrees aislados multiplican contexto por N (+200% tokens), CLI inestable, orquestación duplicada.
**Solución:** descartar la herramienta; anexar su aporte nativamente como `harness/orchestrator/parallel_executor.py`: fan-out paralelo (ThreadPoolExecutor, max_workers=3) sobre MultiAPIProvider.execute + `vote_on_task` con votación gobernada (gate score≥70 ∧ confidence<0.7, N=3, presupuesto MAX_TOKENS_BY_AGENT×3) + `get_stats()` con métricas fan_out_factor / tokens_per_parallel_agent / voting_events registradas en token_budgets.yaml.
**Tests:** 21 (test_parallel_executor.py).
